## 一、Agent自主执行闭环

### 1.1 功能描述

**是什么**: 将AI Agent从当前的"辅助对话"模式升级为"自主执行"模式。Agent可自主完成多步骤编程任务，包括文件读写、代码修改、命令执行、测试验证等完整开发闭环。

**解决什么问题**: 
- 用户需要反复确认每一步操作，效率低下
- 复杂任务需要手动拆解和编排
- 执行过程不可视、不可追溯、不可回滚

**目标用户**: 所有使用IDE模式的开发者，特别是需要处理重复性任务或大型重构的开发者。

#### 场景2: 创建新功能

```
Agent自动:

  7. 生成单元测试
```

#### 场景3: 依赖升级

```
用户: "把所有的 @mui 依赖从 v7 升级到 v8，修复 Breaking Changes"

Agent自动:
  1. 解析 package.json 找到所有 MUI 依赖
  2. 逐个检查 MUI v8 的 Breaking Changes 列表
  3. 识别需要修改的组件和使用方式
  4. 生成迁移计划供用户确认
  5. 逐个文件执行修改
  6. 运行类型检查和测试
```

### 1.5 技术要求和限制

| 要求 | 说明 |
|------|------|
| **沙箱环境** | 使用WebContainer API（浏览器内Node.js环境），不可用则降级为Docker API |
| **权限模型** | 4级权限：READ_ONLY / SANDBOX / CONFIRMED / AUTONOMOUS |
| **执行超时** | 默认5分钟，可配置。超时自动终止并保存检查点 |
| **回滚机制** | 文件级回滚（基于备份快照），Git级回滚（基于git stash） |
| **并发限制** | 同时最多1个Agent任务，防止资源竞争 |
| **文件限制** | 单次任务最多修改50个文件，防止批量破坏 |
| **状态持久化** | 浏览器关闭不丢失，基于IndexedDB保存任务状态 |
| **新增Store** | agent-executor-store（Zustand + immer + persist） |
| **新增Service** | sandbox-engine, task-orchestrator, rollback-manager |

## 二、多模态AI交互

### 2.1 功能描述

**是什么**: 在现有文本对话基础上，新增语音输入、截图提问、白板绘图三种交互方式。

**解决什么问题**:
- 键盘输入效率瓶颈（语音比打字快3倍）
- 描述UI问题时截图比文字更直观
- 架构设计时绘图比打字更自然

### 2.2 用户场景

#### 场景1: 语音编程

```
用户说话: "帮我在 src/utils 下创建一个 date-formatter.ts，

Agent: (识别语音 → 理解意图 → 创建文件)
  ✅ 已创建 src/utils/date-formatter.ts
  ✅ 已实现 formatDate(date: Date, format: string): string
```

#### 场景2: 截图提问

```
用户: (截图一个报错界面，拖入对话框)
     "这个错误怎么修复？"

  2. 添加默认值: (users ?? []).map(...)
```

## 三、Tauri桌面应用

### 3.1 功能描述

**是什么**: 将Web应用打包为原生桌面应用（macOS/Windows/Linux），通过Tauri 2.x框架实现系统级功能集成。

**解决什么问题**:
- 完全离线使用需求
- 系统级功能集成（托盘、全局快捷键、原生通知）
- 文件关联和系统集成
- 更低的资源占用

### 3.2 用户场景

#### 场景1: 系统托盘常驻

```
用户日常工作流:
  1. 开机自动启动YYC³在系统托盘
  2. 通过全局快捷键 ⌘⇧Space 随时唤起
  3. 点击托盘图标展开快捷菜单:
     ┌─────────────────┐
     │ 📝 新建笔记     │
     │ 💻 打开IDE      │
     │ 🤖 AI助手       │
     │ 📊 系统状态     │
     │ ⚙️ 设置        │
     │ ───────────── │
     │ ❌ 退出        │
     └─────────────────┘
```

#### 场景2: 离线完整包

```
用户下载 200MB 离线包（含小型AI模型）:
  - 无需联网即可使用所有功能
  - 代码补全使用本地小模型
  - 智能问答使用本地模型
  - 需要大模型时可选择连接云端API
```

### 3.3 技术要求

| 要求 | 说明 |
|------|------|
| **Tauri版本** | Tauri 2.x (stable) |
| **Rust后端** | 系统托盘、文件操作、全局快捷键、自动更新 |
| **包体积** | 基础包 < 10MB（不含模型），完整包 < 200MB |
| **平台** | macOS 12+, Windows 10+, Ubuntu 20.04+ |
| **新增目录** | tauri-app/src-tauri/ (Rust源码) |
| **新增配置** | tauri-app/tauri.conf.json |

## 八、UI/UX设计规范

### 8.1 新增组件命名规范

```
所有新增组件采用一致的命名模式:
  - 面板类: <功能名>Panel.tsx     (如: AgentExecutorPanel)
  - 按钮类: <功能名>Button.tsx    (如: VoiceInputButton)
  - 弹窗类: <功能名>Modal.tsx     (如: PluginInstallModal)
  - 部件类: <功能名>Widget.tsx    (如: ProgressWidget)

遵循现有目录结构:
  src/app/components/
    AgentExecutorPanel.tsx         (P0: Agent执行)
    AgentTaskProgress.tsx           (P0: 任务进度)
    VoiceInputButton.tsx            (P0: 语音输入)
    DrawingBoard.tsx               (P0: 白板绘图)
    ScreenCaptureOverlay.tsx       (P0: 截图覆盖层)
    KnowledgeGraphPanel.tsx        (P1: 知识图谱)
    RelatedFilesPanel.tsx           (P1: 关联文件)
    PluginMarketPanel.tsx           (P1: 插件市场)
    PluginDetail.tsx               (P1: 插件详情)
    TeamSpacePanel.tsx             (P1: 团队空间)
    CollabPermissionModal.tsx      (P1: 权限管理)
    ContentDashboard.tsx           (P1: 内容数据)
    MultiPlatformPublisher.tsx     (P1: 多平台发布)
```

### 8.2 设计原则

| 原则 | 说明 |
|------|------|
| **一致性** | 新组件UI风格与现有Cyberpunk/Clean主题完全一致 |
| **渐进增强** | 高级功能在不支持时优雅降级，不影响核心体验 |
| **可访问性** | 所有组件满足WCAG 2.1 AA标准，支持键盘导航 |
| **响应式** | 面板支持拖拽调整大小，适配不同屏幕 |
| **动画** | 使用motion库（项目已有），动画自然流畅 |
| **加载态** | 使用LoadingSkeleton（项目已有），避免空白等待 |
